## Required corrections

### R1 — P1: legacy watch automatically redispatches after A2A cancellation

Location: `bin/handoff`, `cmd_watch`, particularly lines 495–510 at the reviewed commit; the transition from outstanding-run reconciliation to legacy dispatch does not consult the saved workflow hold.

Reproduced twice with a fake A2A worker and a harmless legacy executable that only writes a launch marker:

1. Approve and start A2A work; worker writes READY FOR QA early and continues running; client times out.
2. Change configuration to `{"transport":"legacy"}` and start the public `handoff watch`.
3. Cancel the outstanding A2A run through `handoff cancel`. Cancellation stops the worker, records `dispatch_hold=true`, consumes one round, restores READY FOR EXECUTION, and clears the outstanding pointer.
4. On its next poll, legacy watch sees READY FOR EXECUTION and **launches the legacy worker without Planner review**. The hold remains true in workflow.json.

This is a concrete automatic-dispatch safeguard failure, not a concurrent-write claim: the canceled A2A worker stopped, but an unrequested replacement starts immediately. The newly fixed saved-endpoint recovery works; the hold is lost at the next transport boundary.

**Fix:** preserve the failed/canceled workflow's dispatch hold across transport selection and reconciliation. Automatic watchers must not clear or ignore it. Require the existing explicit reviewed-action path before another launch. Keep ordinary legacy repositories without A2A state Python-free.

**Acceptance:** actual CLI tests for switching to legacy and removing config while a run is outstanding, then canceling or receiving failure. Watch must remain held with exactly one worker launch. Also retain successful-completion notification and explicit reviewed-execution behavior. No server lifecycle rewrite or paid call is needed.

### R2 — P2: Codex's handoff loading stops working when AGENTS.md exists

Location: `src/handoff_a2a/adapters/codex.py`, `CodexAdapter.argv`, lines 219–222 at the reviewed commit.

The adapter relies on `project_doc_fallback_filenames=["HANDOFF.md"]` to deliver the git-excluded plan. Independent `codex debug prompt-input` inspection using the adapter's configuration overrides showed:

| Fixture | Handoff sentinel in model input | AGENTS sentinel in model input |
|---|---|---|
| Git-excluded HANDOFF.md, no AGENTS.md | Yes | No |
| Same fixture, ordinary nonempty AGENTS.md added | **No** | Yes |

This matches [official Codex instruction discovery](https://learn.chatgpt.com/docs/agent-configuration/agents-md): each directory contributes at most one instructions file, with AGENTS.md preceding fallbacks. The inspection used an empty temporary CODEX_HOME to avoid user configuration; debug prompt inspection does not accept exec's `--ignore-user-config` flag. It made no model call.

**Evidence boundary:** this proves that automatic delivery disappears, not that every live agent will fail to find the file. A Codex agent can still explicitly read HANDOFF.md. However, reliance on ignore-aware file discovery already caused a real failed delivery in the recorded experiment; an ordinary AGENTS.md reintroduces that condition. The replacement path should carry the approved task reliably in this common repository setup.

**Fix:** deliver the validated full handoff deterministically alongside existing repository guidance, preserving the fixed ritual prompt and without overwriting AGENTS.md or modifying Planner orchestration. Keep provider-specific handling in the adapter/server boundary.

**Acceptance:** a model-free prompt/input regression with ordinary AGENTS.md, with AGENTS.override.md, and without either must show both applicable repository guidance and the complete approved handoff. Retain existing contract and fake-worker checks. Do not repeat the full paid comparison for this configuration fix; report clearly if a narrow live check is still required.
